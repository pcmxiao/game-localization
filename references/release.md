# 发布前清理

游戏能跑 ≠ 可以发。最后一步是把所有工作痕迹清掉，
否则用户会看到一个塞满补丁文件和临时表的目录。

## 必须删

- 翻译表 CSV / TSV / JSON（除非明确作为补丁的一部分发布）
- `--dry` 输出、日志、错误报告
- 中间解包目录
- 进度笔记、批次清单
- `.bak` / `.orig` / `~` 结尾的编辑器残留
- 编辑器工作区文件（`.fuse_hidden*`、`.goutputstream-*`）
- `__pycache__` / `.pytest_cache`
- `audit.json` 之类的中间报告

## 绝不删

- `package.json` / `Game.ini` / `www/` 的入口文件
- `js/` 下的任何东西（除非你主动改过且已确认游戏正常）
- `img/` `audio/` `font/` —— 尤其 `font/`，删了字全变豆腐块
- `plugins/` 目录（RPG Maker 的自带插件）
- `data/` 下的 `*.json` —— 这是你的译文载体，删了等于还原
- 你放进去的新字体文件

## 检查清单

发布前逐条确认：

- [ ] 游戏能从头启动，不弹「项目数据被外部修改」
- [ ] 主菜单、系统菜单、设置项已译
- [ ] 随便跑一段剧情 —— 对话、选项、立绘、表情、变量显示正常
- [ ] 打一场战斗 —— 战斗提示、技能名、状态名正常
- [ ] 存一次档、读一次档 —— 读档后文本正常
- [ ] 全屏 / 窗口切换后文本不溢出
      （中日文比原文短，一般没问题；往更长的语言翻时要注意）
- [ ] 新字体已包含目标语言所需**全部**字形，不是只包含常用字
- [ ] 没有残留的临时文件
- [ ] 备份目录已移出游戏目录，或明确告知用户位置

## 备份怎么处理

两个选择，明确告诉用户：

- **删掉** —— 干净，但没退路
- **保留并告知路径** —— 用户能自己回滚，但目录里多一个文件夹

不要默默留着。

本仓库的 `apply_sheet.py` 默认备份到 `<游戏目录的同级>/gameloc_backups/`，
即**在游戏目录之外**。这是故意的：备份放在游戏目录里，清理时很容易把自己删了。

```bash
# 覆盖时自动产生带时间戳的新备份目录
gameloc_backups/
├── rpgmaker-mvmz_20261008_213015/
└── rpgmaker-mvmz_20261008_221530/
```

## 最后一步：审计报告怎么处理

`audit.py` 的 `--report audit.json` 里包含**游戏原文**。
如果要分享汉化成果或提 issue，这份文件不应外发 —— 它等于把原文抄了一遍，
而且可能涉及版权。

分享时只报数字和分类统计，不要贴具体条目。
